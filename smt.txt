=========================================================
INSTANCING, STATIC MESHES & MESH OPTIMIZATION
=========================================================

This engine should prioritize intelligent rendering performance while remaining intuitive and flexible for developers and artists.

The engine should automatically reduce unnecessary draw calls whenever possible without changing the user's workflow.

Users should not be forced to manually optimize every scene.

The renderer should intelligently batch compatible objects automatically.

=========================================================
STATIC MESH ACTORS
=========================================================

A Static Mesh Actor represents a single independent object placed inside the scene.

Each Static Mesh Actor owns:

• Transform
• Mesh
• Materials
• Physics Components
• Lua Components
• Metadata
• Tags
• Layers

Every Static Mesh Actor has its own Position, Rotation and Scale.

Every Static Mesh Actor can be modified independently.

Static Mesh Actors are ideal for:

Buildings

Props

Furniture

Rocks

Vehicles

Bridges

Decorations

=========================================================
INSTANCED STATIC MESHES
=========================================================

The engine should support Instanced Static Meshes (ISM).

Instancing allows one mesh to be rendered thousands of times while sharing the same geometry and materials.

Each instance should maintain its own independent transform.

Every instance must support:

• Position

• Rotation

• Scale

• Visibility

• Selection

• Layer

• Tags

Additionally, every instance should support per-instance rendering data such as:

• Color Tint

• Wind Strength

• Random Seed

• Material Parameters (where supported)

This allows each instance to appear visually unique while still sharing the same mesh and material resources.

Examples:

Tree A

Rotation = 15°

Scale = 1.1

Random Seed = 42

Tree B

Rotation = -18°

Scale = 0.85

Random Seed = 99

Tree C

Rotation = 63°

Scale = 1.35

Random Seed = 14

Although every tree looks slightly different, they all use the same underlying mesh and are rendered efficiently through GPU instancing.

=========================================================
HIERARCHICAL INSTANCED STATIC MESHES (HISM)
=========================================================

For extremely large scenes, support Hierarchical Instanced Static Meshes.

Examples:

Large Forests

Grass

Rocks

Street Lights

Fences

Buildings

The renderer should spatially organize instances into hierarchical clusters.

Only visible clusters should be rendered.

This minimizes CPU work and GPU draw calls.

=========================================================
AUTOMATIC GPU INSTANCING
=========================================================

The engine should automatically detect compatible objects.

If multiple objects share:

• Same Mesh

• Same Material

• Same Rendering Settings

The renderer should automatically batch them internally.

This optimization should happen automatically whenever possible.

Artists should not be forced to manually create instance groups for common cases.

The editor should continue to display individual objects for easy editing.

Rendering optimizations should remain transparent to the user.

=========================================================
INSTANCE VARIATION
=========================================================

Instances should never be limited to looking identical.

The engine should support per-instance variation using shader data.

Supported variation includes:

• Random Rotation

• Random Scale

• Color Tint

• Wind Animation

• Material Parameters

• Random Seed

• Custom Instance Data

Shaders should be capable of reading this data to create natural visual variation without creating duplicate meshes.

This is especially useful for:

Trees

Grass

Flowers

Rocks

Props

Crowds

Vegetation

=========================================================
CONVERT INSTANCE TO UNIQUE OBJECT
=========================================================

Artists should be able to select any instance and choose:

Convert to Unique Object

Only that instance becomes an independent Static Mesh Actor.

All remaining instances continue using GPU instancing.

The newly created object can then be modified freely without affecting the original instanced group.

=========================================================
MESH MERGING
=========================================================

Mesh Merging should exist as a manual optimization tool.

It should never happen automatically.

Mesh Merging permanently combines multiple meshes into one new mesh asset.

Merged meshes reduce draw calls but lose independent transforms.

Use Mesh Merge only for geometry that will never move independently.

Examples:

Building Walls

Architecture

Ruins

Large Decorative Structures

Static Environment Pieces

Do not use Mesh Merge for:

Doors

Characters

Interactive Objects

Physics Objects

Moving Platforms

Animated Props

=========================================================
GROUPS
=========================================================

Groups exist purely for scene organization and editing.

Groups own a Transform.

Children inherit that Transform.

Moving a Group moves all children.

Rotating a Group rotates all children.

Scaling a Group scales all children.

Groups are editor conveniences.

Groups are not rendering optimizations.

Groups do not reduce draw calls.

Groups may contain:

Meshes

Lights

Cameras

Effects

Audio

Other Groups

Folders

=========================================================
FOLDERS
=========================================================

Folders exist only for organization.

Folders have no Transform.

Folders cannot affect gameplay.

Folders simply organize the Hierarchy.

Folders support:

Rename

Move

Delete

Duplicate

Search

Color Labels

Visibility

Lock

Nested Folders

=========================================================
RENDERING PHILOSOPHY
=========================================================

The engine should always prioritize:

Automatic GPU optimization

Minimal draw calls

Minimal CPU overhead

Minimal memory duplication

High scalability

Ease of use

Developers should spend their time creating games rather than manually optimizing every scene.

The renderer should intelligently optimize compatible objects automatically while preserving complete editing flexibility inside the editor.

Optimization should remain largely invisible to the user.

=========================================================
ENGINE PHILOSOPHY
=========================================================

Everything should remain data-driven.

Everything should integrate naturally with ECS.

Everything should support hot reload where appropriate.

Everything should be modular.

Everything should be scalable.

Everything should be maintainable.

Every optimization should preserve usability.

The engine should feel modern, elegant, responsive, and approachable for beginners while still providing the performance expected from a professional AAA-quality engine.
